# 后续实现计划

截至 2026-11-09 的路线。阅读器与词库（M1）已经可用，接下来的目标不是继续加阅读页的花样，而是把产品
说明书的下一段闭环补齐：**在词库管理 → 用它做练习 → 回到原文**。
英语基础是独立内容工程，放在闭环之后；阅读器的发音、划词、全文搜索、普通文章不阻塞主链路，排在最后。

## 现状基线

| 项 | 状态 |
|---|---|
| 阅读 | 左右对照 / 单栏、BSB / WEBP / KJV + 和合本、66 卷选章、书签、点词查卡、记住位置 |
| 词典 | 41,873 条，Open Dictionary 中文 + WordNet 英文释义 + CMUdict 音标 + ACAI 圣经专名；无发音音频、无词源 |
| 收藏 | 查词卡底部「收藏这个词」，存表面形式、词形、释义、本句中英原文，写入 `vocab.json` |
| 页上标记 | 收藏的词按阶段画底纹：生词浅、学习中最深、已掌握不画 |
| 词库 | 三栏（筛选 196 / 列表 330 / 详情）、计时计数、搜索、手动添加、三阶段、删除确认、回到原文并开卡 |
| 全部词典 | 词库顶栏切「我的词 / 全部词典」：41,873 条按字母排序，A–Z 跳转、前缀搜索、直接收藏（M1 之外，2026-11-09 加） |
| 练习 / 英语基础 | 原生端还没有页面 |
| 导航 | 54px 顶栏下 68px 模块轨，只点亮阅读 / 词库，其余不可用 |
| 框架能力 | `flex.Field` 文本输入、`ScrollArea`、`Table`、`Tabs` 可用；路径图标在真实窗口里不落像素（见 `viva-framework-issues.md` §7）；没有音频播放 API |

## 路线总览

| 阶段 | 交付 | 依赖 | 完成标准 |
|---|---|---|---|
| M1 生词本 | 模块导航、查词卡收藏、词库页、手动添加、阶段管理、原句语境 | 无 | 收藏在重启后仍在；同一词不重复；能从词库跳回原句 |
| M2 练习 | 单词跟打 / 默写 / 自测，经文跟打 / 填空，即时反馈、错词、简单复习 | M1 | 练过的词有对错记录；错词进「错词」筛选；可再练一遍 |
| M3 英语基础 | 音标、语法、词根与派生、基础词汇的只读参考 + 小测 | 无（内容自备） | 内容可检索；派生与词源不混说；不依赖阅读 |
| M4 阅读器深度 | 划词/短语收藏、发音、全文搜索、普通文章 | M1、M2 | 不改变现有阅读布局与键盘操作 |

先做 M1 的原因：练习没有素材就是空壳，而收藏入口、语境和本地存储是 M2 的直接输入。M3 的内容要逐条
编写和校对，适合与 M1/M2 并行，但不适合抢在闭环前面。

## M1 生词本（已完成）

2026-11-09 落地：`internal/vocab` 数据层、查词卡收藏、68px 模块轨、三栏词库、搜索、手动添加、
三阶段、删除确认、原句跳回（落到该节并打开这个词的卡片）、`state.json` 的 `Saved` 迁移；正文里
收藏过的词按阶段画底纹。UI 细节后续按使用反馈再调，本节的界面描述是当前实现的规格来源。

### 界面

- 左侧 68px 模块轨（放在 54px 顶栏之下，顶栏保持全宽、logo 不动）：阅读 / 词库 / 练习 / 英语基础，
  当前项高亮。图标暂用两字中文标签，因为
  `ui.Icon` / `DrawPath` 在真实窗口不出像素；若要做图标，先用脚本生成 PNG 再走 `flex.Image`，
  不引入路径图元。M1 只点亮「阅读 / 词库」，其余显示为不可用。
- 查词卡底部加一个「收藏」按钮。收藏时把当前词、词形关系、词典释义和这一节的中英原文一起存下；
  已收藏则显示「已收藏」，再点取消收藏。
- 词库页三栏：左筛选 196px（全部 / 生词 / 学习中 / 已掌握 / 错词，带计数），中间列表 330px
  （词 + 音标 + 中文 + 阶段），右侧详情占余下宽度（词头、音标、词性、中文、英文释义、原形、阶段、
  原句列表与「回到原文」、删除），整体限宽 1240 居中；「去练习」等 M2 的练习页存在后再接。
  三栏宽度与文案以本文件为准，界面直接用 `cmd/shot` 截图验收。
- 搜索框按词、中文、原句做大小写不敏感的子串匹配；词库规模是个人收藏量，不需要索引。
- 手动添加：输入单词或短语，先查词典；查不到也允许保存，详情里明说「词典未收录」，不补写释义。
- 详情里的原句可点击，跳回阅读器对应的卷、章、节；跳转后把该词的卡片开在它所在的词上，
  阅读位置按节重新定位。
- 正文里收藏过的词带淡底纹：生词最浅、学习中最深，已掌握不画，回到和正文一样的外观。
- 空状态写清楚入口：「还没有收藏的词。阅读时点一个词，选『收藏』。」

### 存储

新增 `internal/vocab`，独立文件 `~/Library/Application Support/bible-en-study/vocab.json`，
与阅读位置 `state.json` 分开：词库会随使用增长，阅读位置每次翻页都写，混在一起会放大写放大。
文件带 `version`，写入用临时文件 + rename，损坏时按空词库处理并保留原文件。

```json
{
  "version": 1,
  "words": [
    {
      "word": "created",
      "lemma": "create",
      "pos": "verb",
      "ipa": "kriˈeɪtɪd",
      "zh": ["创造"],
      "senses": ["to bring into existence"],
      "stage": "new",
      "added": "2026-11-08T10:00:00+08:00",
      "contexts": [
        {
          "translation": "BSB",
          "book": "Gen",
          "chapter": 1,
          "verse": 1,
          "en": "In the beginning God created the heavens and the earth.",
          "zh": "起初，神创造天地。"
        }
      ],
      "right": 0,
      "wrong": 0,
      "lastReview": "",
      "due": ""
    }
  ]
}
```

- 去重按小写比较，但 `word` 保留用户点到的表面形式（`I`、`God` 不改成小写）；保留 `lemma` 说明
  词形关系，练习默认拼写用户收藏的那个形式，不擅自改成原形。
- 同一节重复收藏不新增语境；不同节保留多条，按加入时间倒序。
- `stage` 三态由用户手动切换，练习不偷偷改阶段；错词由 `wrong > 0` 派生。
- 迁移：首次加载时把旧 `state.json` 的 `Saved` 转成没有语境的条目，词性 / 音标 / 中文 / 英文释义尽量
  用词典补齐；`vocab.json` 写成功后才清掉 `Saved`，转换成功后不再以 `Saved` 为准，字段保留只为旧文件可读。
- 删词是硬删除，但先弹确认；不做回收站。

### 验收

- 收藏 → 切到词库 → 看到词和原句 → 重启后仍在。
- 同一词重复收藏不产生第二条；同一节重复收藏不产生第二个语境。
- 词典未收录的词/短语能保存，详情明确显示未收录。
- 词库里的原句能跳回正确的卷、章、节。
- `go test ./...` 全绿；`vocab` 的单测覆盖去重、损坏文件、原子写入，`state.json` 的迁移由 `desk` 的测试覆盖。
- 用 `cmd/shot` 出词库列表、详情、空状态三张图，人工看排版。

### 施工顺序（已按此落地）

M1 分五片推进，每片可单独提交、单独回退：

1. `internal/vocab` 数据层，不碰 UI：`Open` / `Save` / `Add` / `Find` / `Remove` / `SetStage`；大小写不敏感去重、
   同节语境去重、`version: 1`、临时文件 + rename、损坏或未知版本保留为 `vocab.json.bad` 后按空库启动。
   单测覆盖往返、去重、语境顺序、损坏、版本。完成标准：`go test ./internal/vocab` 绿，窗口行为不变。
2. 收藏闭环：`State` 持 `*vocab.Store`，在 `Config` 里加载（测试和 `cmd/shot` 都走这里，不能只放 `restore`）；
   旧 `State.saved` 与 `remember` 的写入移除，迁移写成功后才清 `state.json` 的 `Saved`；查词卡底部加
   「收藏 / 已收藏」，存词、lemma、pos、ipa、zh、senses 和本节中英原文；`openLookup` 单栏下也取中文。
   完成标准：收藏 → 重启仍在；同词、同节不重复。
3. 模块轨 + 词库骨架：`Module` 枚举、68px 轨（只点亮阅读 / 词库）、词库顶栏（标题 / 搜索 / 添加）、左筛选 +
   计数、中列表、右详情空态；词库三栏整体限宽 1240 居中；接上 `config.TextInput`、`config.OnScroll`；
   `OnKey` 只在阅读模块翻页。
   完成标准：切换不丢阅读位置；列表 / 计数 / 搜索来自真实词库；980×640 不溢出。
4. 详情与增删：词头、音标、词性、中文、英文释义、词形、三阶段、原句列表、删除确认；手动添加对话框
   （输入时显示词典预览，查不到也允许保存，重复添加选中已有词条）。完成标准：阶段筛选、删除确认、
   已收录 / 未收录 / 重复添加四条路径都走通。
5. 原句跳回 + 验收：`pendingVerse` 在排版后定位到含该节的 spread，找不到就停章首；跳转不偷换译本；
   `go test ./...`；`cmd/shot` 出列表 / 详情 / 空态三张图；更新 `app/README.md` 与本文件 M1 状态。

两个实现细节先记下：查词卡新增一行按钮后，卡片「放上方 / 下方」的 330 / 310 估算要一起调大；词库过滤
每次重绘计算，个人收藏量不做索引或缓存。

980 宽下模块轨让每页正文 measure 从 338 降到约 304；M1 先接受，片 3 在最小窗口看实际阅读页，
若不可读，再决定提高最小窗宽还是窄屏隐藏轨。

## M2 练习

### 单词四式

| 模式 | 题面 | 输入 |
|---|---|---|
| 跟打 | 单词 + 音标 + 中文 | 照着拼 |
| 默写 | 中文 + 词性 + 首字母/长度提示 | 回忆拼写 |
| 自测 | 单词遮掉部分字母（如 `c_e_t_d`） | 补全整个词 |
| 听写 | 暂缓：没有音频 API，也没有随包音频 | — |

- 题源默认取词库里的「生词 + 学习中 + 到期」；一轮 12 个，先到期、再新词，随机打散；没有可练的词就显示
  空状态并给「去阅读」入口。
- 逐字符即时对比：对绿错红，不自动跳题；Enter 提交/下一题，Esc 退出。界面上只显示「3 / 12」这类进度，
  不显示分数、速度、连击。
- 结果页只列本轮错词和「再练一遍」，不引入等级或奖励。
- 记录写回 `vocab.json`：`right`、`wrong`、`lastReview`、`due`。间隔先用最简单的规则：
  错 → 1 天后；对 → 3 / 7 / 14 / 30 天递增。这是可选的复习提示，不生成每日任务。

### 句子与经文

- 经文跟打：显示当节英文，用户整句输入；比较时忽略大小写、空白和标点，只比字母、撇号与连字符，
  标点仍显示在题面里。这样练的是拼写和词序，不是标点。
- 经文填空：从当前节里选收藏词（没有收藏词就选内容词）挖一个空，显示中文和带空的英文，输入缺的词。
  一次一个空，不做一个句子多个内联输入框。
- 结果同样写回单词记录；句子本身不单独建库，避免又一套内容管理。

### 验收

- 三种单词模式都能出题、判对错、进下一题；错词进入「错词」筛选。
- 经文跟打对标点/大小写不敏感，对拼写和词序敏感。
- 退出再进，统计和到期时间还在；重复练同一个词会更新 `lastReview`。
- 全键盘可完成一轮；不出现计时器、分数或游戏化文案。
- 单测覆盖判分规则、队列挑选、间隔计算；`cmd/shot` 出练习进行中和结果页。

## M3 英语基础

这一阶段的主要成本是内容，不是代码。全部内容放在 `internal/basics/basics.json`，随二进制内嵌，
不联网；每条都要有出处或标注为自行编写，不把生成式内容当事实。

- 音标：44 个音素、例词、最小对立对；只做「看音标选单词」这类不依赖音频的小测。
- 语法：12 个主题（词性、句子成分、基本句型、时态、短语、从句等），每个主题解释 + 2–3 个例句。
- 词根与派生：约 30 组常用前缀/后缀/词根；词族关系只使用词典里能验证的屈折与派生，明确区分
  「词形变化 / 派生 / 词源」，没有可靠词源就不写词源。
- 基础词汇：先做 300 个高频词，含中文、音标、一个例句；与词库共用查词卡，不另造一套词典。
- 界面：四个标签页 + 搜索；只读为主，小测独立入口；不要求先读圣经。

验收：四类内容都能检索；派生关系有词典依据；没有编造的词源；窄窗口下正文不溢出。

## M4 阅读器深度

- 划词/短语：拖选或 Shift 点选相邻词，浮层给「收藏短语」；短语查不到词典时只存文本和语境。
- 发音：优先评估 macOS 系统 `say`（离线、无新 Go 依赖，但依赖系统语音、不可移植）；若不可接受，
  改为随包音频，但会显著增大体积。听写模式跟着发音一起做。
- 全文搜索：在 `cmd/bibledata` 建词→经节倒排索引写进 `store.bin`，阅读页提供搜索面板；
  不扫描 SQLite。
- 普通文章：把阅读器的数据源从 `bible.Store` 抽成只读接口，文章以纯文本/Markdown 导入，
  存在用户目录而不是二进制里；这一步会触碰「单文件离线」的边界，单独评估。
